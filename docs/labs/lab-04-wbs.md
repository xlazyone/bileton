# Лабораторная работа №4. Построение иерархической структуры работ (WBS)

## 1. Основные результаты (deliverables) верхнего уровня

Мы отказались от деления по фазам (Waterfall) и перешли на деление по функциональным блокам и обеспечивающим процессам.

| Код | Deliverable (Блок) | Ответственные роли |
| :---- | :---- | :---- |
| 1.0 | Управление проектом и документация (Командный менеджмент) | \[PM\], \[Вся команда\] |
| 2.0 | Организация инфраструктуры (DevOps) | \[Lead Dev\], \[QA\], \[PM/Backend\] |
| 3.0 | Модуль «Авторизация и профиль» | Конвейер: \[Аналитик\], \[PM/Backend\], \[Frontend\], \[QA\] |
| 4.0 | Модуль «Афиша и сеансы» | Конвейер: \[Аналитик\], \[PM/Backend\], \[Frontend\], \[QA\] |
| 5.0 | Модуль «Бронирование мест» | Конвейер: \[Аналитик\], \[Lead Dev\], \[Frontend\], \[QA\] |
| 6.0 | Модуль «Оплата и QR» | Конвейер: \[Аналитик\], \[Lead Dev\], \[Frontend\], \[QA\] |

пунктами не выделяются: панель контроллера и сквозное тестирование вошли в блок
6.0, а финальный деплой, User Manual и подготовка к защите перенесены в блоки
2.0 и 1.0 (задачи 2.6, 1.7 и 1.9). Общее количество задач и трудоёмкость при этом
не изменились.

## 2. WBS в виде нумерованного списка

**1.0. Управление проектом и документация (Командный менеджмент).**

1.1. \[PM\] Разработка Устава проекта, согласование со стейкхолдерами. (8 ч)

1.2. \[Вся команда\] Декомпозиция WBS, построение диаграммы Ганта. (4 ч)

1.3. \[PM\] Модерация Scrum-событий (планирование спринтов, дейли, ретро). (16 ч)

1.4. \[Вся команда\] Участие в ежедневных летучках и обновление статусов в Trello/Jira. (16 ч)

1.5. \[PM\] Ведение реестра рисков и расчет метрик EVM по ЛР. (8 ч)

1.6. \[Вся команда\] Финальная ретроспектива (Start-Stop-Continue). (2 ч)

1.7. \[PM\] Внедрение и сопровождение User Manual (инструкции для пользователя и контроллера). (4 ч)

1.8. \[PM\] Сборка портфолио и подготовка презентации к защите. (8 ч)

1.9. \[Вся команда\] Подготовка к защите, сдача проекта 13 декабря. (4 ч)

**2.0. Организация инфраструктуры разработки (DevOps)**

2.1. \[PM/Backend\] Инициализация Git-репозитория, настройка Git-flow (main, dev, feature). (4 ч)

2.2. \[Lead Dev\] Разработка инструкции по локальному запуску проекта (readme). (4 ч)

2.3. \[PM/Backend\] Настройка пайплайна CI (GitHub Actions для автозапуска линтеров/тестов). (6 ч)

2.4. \[QA\] Развертывание локальной СУБД PostgreSQL для тестов. (4 ч)

2.5. \[Lead Dev\] Настройка скриптов деплоя на тестовый сервер (VPS). (6 ч)

2.6. \[Lead Dev\] Деплой финальной версии на сервер. (4 ч)

**3.0. Модуль «Авторизация и профиль» (Спринт 1)**

3.1. \[Аналитик / QA\] Написание Use Cases и критериев DoD для входа/регистрации. (4 ч)

3.2. \[PM / Backend\] Проектирование и создание таблицы users. (4 ч)

3.3. \[Lead Dev\] Реализация JWT-авторизации и разграничения ролей (зритель/контроллер). (12 ч)

3.4. \[Frontend\] Верстка страниц входа и регистрации по макету. (8 ч)

3.5. \[Frontend\] Интеграция форм с API авторизации (сохранение токена). (6 ч)

3.6. \[Аналитик / QA\] Написание чек-листа тестирования безопасности. (2 ч)

3.7. \[Frontend / QA\] Прогон тестов, заведение багов в Jira (например, «не работает валидация пароля»). (4 ч)

**4.0. Модуль «Афиша и сеансы» (Спринт 2)**

4.1. \[Аналитик\] Формирование User Stories на просмотр афиши и расписания. (2 ч)

4.2. \[PM / Backend\] Создание таблиц movies, sessions. (6 ч)

4.3. \[Lead Dev\] Разработка эндпоинтов GET /movies и GET /sessions. (8 ч)

4.4. \[Frontend\] Верстка карточек фильмов и страницы выбора сеанса. (10 ч)

4.5. \[Frontend\] Подключение API афиши к интерфейсу. (6 ч)

4.6. \[Аналитик / QA\] Написание тест-кейсов на отображение пустого расписания. (2 ч)

4.7. \[Frontend / QA\] Проверка верстки на разных разрешениях, фикс багов. (6 ч)

**5.0. Модуль «Схема зала и бронирование» (Спринт 3)**

5.1. \[Аналитик\] Описание логики блокировки мест при одновременном бронировании. (4 ч)

5.2. \[PM / Backend\] Разработка структуры таблиц halls, seats, bookings. (6 ч)

5.3. \[Lead Dev\] Реализация API POST /bookings с использованием SELECT FOR UPDATE для защиты от двойных продаж. (16 ч)

5.4. \[Frontend\] Верстка интерактивной схемы зала (CSS Grid, статусы мест: свободно/занято/выбрано). (14 ч)

5.5. \[Frontend\] Интеграция: отправка запроса на бронь и обработка ошибки HTTP 409 (место занято). (8 ч)

5.6. \[Аналитик / QA\] Написание скрипта для имитации одновременного бронирования (нагрузочный тест). (8 ч)

5.7. \[Frontend / QA\] Прогон сценариев, проверка отката транзакции. (6 ч)

**6.0. Спринт 4. Оплата, генерация QR, панель контроллера и финальное тестирование.**

6.1. \[Аналитик\] Сценарий "успешной/неуспешной оплаты" и формат данных для QR. (3 ч)

6.2. \[PM / Backend\] Создание таблицы tickets, связь с bookings. (4 ч)

6.3. \[Lead Dev\] Имитация оплаты. Подключение библиотеки qrcode для генерации билета. API для получения QR. (12 ч)

6.4. \[Frontend\] Верстка страницы оплаты и личного кабинета с билетами. (8 ч)

6.5. \[Frontend\] Отрисовка QR-кода на экране телефона (получение base64 через API). (6 ч)

6.6. \[Аналитик / QA\] Тестирование сценариев сбоя оплаты (отклонение транзакции). (4 ч)

6.7. \[Frontend / QA\] Проверка читаемости сгенерированного QR-кода обычным сканером. (4 ч)

6.8. \[Аналитик\] Требования к интерфейсу контроллера (ввод кода/сканирование). (2 ч)

6.9. \[Lead Dev\] API валидации билета (статус: действителен/просрочен/подделка). (6 ч)

6.10. \[Frontend\] Верстка страницы контроллера (поле ввода, вывод результата проверки). (6 ч)

6.11. \[Frontend\] Интеграция страницы с API валидации. (4 ч)

6.12. \[Аналитик / QA\] Создание базы тестовых QR-кодов (валидные, фейковые, уже использованные). (4 ч)

6.13. \[Frontend / QA\] Тестирование проходного режима. (4 ч)

6.14. \[Вся команда\] End-to-End тестирование: от регистрации до прохода по QR-коду. (8 ч)

6.15. \[Аналитик / QA\] Регрессионное тестирование (проверка, что новые фичи не сломали старые). (8 ч)
