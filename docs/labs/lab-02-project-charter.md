Лабораторная работа №2. Разработка Устава проекта (Project Charter)

**1\. Цель проекта по SMART**  
Формулировка цели:  
Создать к 13 декабря (до начала сессии) работающий MVP веб\-сервиса «БилетON», позволяющий пользователю выбрать сеанс, забронировать конкретное место на схеме зала и получить уникальный QR-код билета. Проект реализуется силами команды из 4 человек в условиях жесткого дедлайна (8 недель) за счет параллельной разработки по спринтам и совмещения ролей.

**3\. Высокоуровневые требования к продукту**  
В рамках MVP система должна обеспечивать:

* регистрацию и авторизацию пользователей;  
* просмотр списка фильмов и доступных сеансов;  
* отображение схемы кинозала с визуальным разделением свободных и занятых мест;  
* выбор пользователем конкретных мест;  
* бронирование выбранных мест;  
* предотвращение одновременного бронирования одного места несколькими пользователями;  
* сохранение информации о билетах и бронированиях в базе данных;  
* генерацию уникального QR-кода для электронного билета;  
* проверку QR-кода при входе на сеанс;  
* отображение пользователю информации о приобретенных билетах;  
* предоставление базового интерфейса для работы с системой через веб\-браузер (ПК-версия).

**Основной пользовательский сценарий:**  
пользователь авторизуется → выбирает фильм → выбирает сеанс → выбирает свободные места → подтверждает бронирование → получает электронный билет с QR-кодом → предъявляет QR-код при входе.

**4\. Основные допущения и ограничения**  
**Допущения**

* пользователи имеют доступ к интернету и современному веб\-браузеру;  
* для учебного MVP используется стандартная конфигурация кинозала на 30-50 мест;  
* система ориентирована на один учебный сценарий работы и не предполагает интеграцию с реальными платёжными системами;  
* QR-код используется как электронный идентификатор билета;  
* данные о фильмах, сеансах и залах могут предварительно заноситься в базу данных.

**Ограничения**

* срок разработки – 8 учебных недель;  
* команда состоит из 4 человек;  
* в рамках MVP не реализуется полноценная интеграция с банковскими платёжными системами;  
* на первом этапе поддерживается стандартная прямоугольная схема кинозала;  
* проект реализуется с использованием Python/FastAPI, React, PostgreSQL и библиотеки qrcode;  
* разработка выполняется в рамках учебного проекта и ограниченных временных ресурсов;  
* нулевой бюджет. Использование только бесплатных инструментов и локального хостинга.  
* параллельная разработка требует строгого соблюдения правил работы с Git (ветвление, Pull Request), чтобы избежать конфликтов.
