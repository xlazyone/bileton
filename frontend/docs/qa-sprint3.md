# Спринт 3 — прогон сценариев бронирования и нагрузочный тест

WBS **5.6** «Скрипт имитации одновременного бронирования (нагрузочный тест)» и
**5.7** «Прогон сценариев, проверка отката транзакции».
Основание: [`docs/requirements/seat-reservation-logic.md`](../../docs/requirements/seat-reservation-logic.md) (5.1),
WBS-словарь пакетов 5.4 и 5.6 (`docs/labs/lab-04-wbs.md`).

## 1. Подготовка стенда

1. PostgreSQL запущен, в `backend/.env` указан `DATABASE_URL`.
2. Из папки `backend/`:
   ```bash
   alembic upgrade head
   python -m scripts.seed_demo --reset   # 3 зала с местами, 6 фильмов, сеансы от текущей даты
   uvicorn app.main:app --reload
   ```
3. Из папки `frontend/`: в `.env.local` `VITE_USE_MOCKS=false`, `VITE_MOCK_CINEMA=false`, затем `npm run dev`.
4. Зарегистрировать **двух** пользователей. Второго открыть в окне инкогнито или другом браузере,
   чтобы токены не смешивались.
5. Результат: ✅ — пройдено, ❌ — баг (issue по шаблону «Bug report», номер в «Комментарий»).

## 2. Нагрузочный тест (5.6) — `backend/tests/test_booking_concurrency.py`

pytest + threads: каждый поток — отдельный пользователь со своим соединением с БД, старт
синхронизирован `threading.Barrier`, запросы приходят в PostgreSQL одновременно.
Нужна **отдельная тестовая база** (таблицы в ней пересоздаются; в имени должно быть `test`):

```bash
createdb -U bileton bileton_test          # один раз
cd backend
BILETON_TEST_POSTGRES_URL=postgresql+psycopg://bileton:bileton@localhost:5432/bileton_test \
  pytest tests/test_booking_concurrency.py -v -rxX
```

Windows (PowerShell): `$env:BILETON_TEST_POSTGRES_URL="postgresql+psycopg://…/bileton_test"; pytest tests/test_booking_concurrency.py -v -rxX`.
Без переменной тесты пропускаются (`skipped`) — так они ведут себя в CI, где нет PostgreSQL.
