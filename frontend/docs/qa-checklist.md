# Чек-лист ручной проверки форм входа и регистрации

WBS **3.4.2** «Прогон тестов, заведение багов» · спринт 1 · [Frontend/QA] Скляров Антон
Основание: [`docs/requirements/use-cases.md`](../../docs/requirements/use-cases.md) (UC-01…UC-04, DoD 3.1–3.4).

## Как проверять

1. `cd frontend && npm run dev` → открыть <http://localhost:5173> (именно `localhost`, не `127.0.0.1`).
2. **Прогон 1 — на моках** (`VITE_USE_MOCKS=true`, в шапке плашка «Демо-режим»).
   Тестовые аккаунты: `viewer@bileton.ru` / `password123`, `controller@bileton.ru` / `password123`.
3. **Прогон 2 — на реальном API** (`VITE_USE_MOCKS=false` в `frontend/.env.local`, backend запущен,
   JWT-ветка Lead Dev смержена в `dev`). Аккаунты создаются через форму регистрации.
4. Ответы сервера смотреть в DevTools → **Network** (код ответа, тело запроса).
5. Перед каждым прогоном — DevTools → Application → Local Storage → очистить.
6. Результат: ✅ — пройдено, ❌ — баг (завести issue по шаблону «Bug report» и указать номер), ⏭ — не применимо.

Автотесты тех же сценариев: `npm test` (Vitest, `frontend/tests/`).

## Регистрация (UC-01)

| ID | Проверка | Шаги | Ожидаемый результат | Моки | API |
|---|---|---|---|---|---|
| REG-01 | Пустые поля | Открыть `/register`, нажать «Зарегистрироваться» | У всех 4 полей сообщения: «Введите имя», «Введите email», «Введите пароль», «Повторите пароль». Запрос в Network **не** уходит | | |
| REG-02 | Некорректный email | Email `anton@mail`, остальное корректно | «Введите корректный email», запрос не уходит | | |
| REG-03 | Короткий пароль | Пароль и подтверждение `1234567` (7 символов) | «Пароль должен содержать не менее 8 символов», запрос не уходит | | |
| REG-04 | Граница длины пароля | Пароль и подтверждение `12345678` (8 символов), новый email | Регистрация проходит (201) | | |
| REG-05 | Несовпадение паролей | `password123` / `password124` | «Пароли не совпадают», запрос не уходит | | |
| REG-06 | Занятый email → 409 | Email `viewer@bileton.ru` (на API — уже зарегистрированный) | Ответ **409**; сообщение «Пользователь с таким email уже существует» и ссылка «Перейти ко входу» | | |
| REG-07 | Успешная регистрация → 201 | Все поля корректны, новый email | Ответ **201** с `id, email, full_name, role=viewer, is_active, created_at`; переход на `/login`, зелёное сообщение, email подставлен | | |
| REG-08 | Тело запроса | REG-07, вкладка Network → Payload | `{email, password, password_confirm, full_name}`; email без пробелов по краям | | |
| REG-09 | Ошибка сети (A5) | Только API: остановить backend, отправить форму | Сообщение «Не удалось связаться с сервером…», введённые данные **остались** в форме | ⏭ | |
| REG-10 | Двойной клик | Быстро дважды нажать «Зарегистрироваться» | Уходит один запрос, кнопка на время запроса заблокирована («Регистрируем…») | | |

## Вход (UC-02)

| ID | Проверка | Шаги | Ожидаемый результат | Моки | API |
|---|---|---|---|---|---|
| LOG-01 | Пустые поля | Открыть `/login` | Кнопка «Войти» заблокирована, пока email или пароль пустые | | |
| LOG-02 | Некорректный email | Email `viewer`, любой пароль | «Введите корректный email», запрос не уходит | | |
| LOG-03 | Неверный пароль → 401 | `viewer@bileton.ru` / `wrong-password` | Ответ **401**; сообщение «Неверный email или пароль» | | |
| LOG-04 | Несуществующий email → 401 | `nobody@bileton.ru` / `password123` | Ответ **401**; **то же** сообщение, что в LOG-03 (не раскрываем, что именно неверно) | | |
| LOG-05 | Успешный вход зрителя | `viewer@bileton.ru` / `password123` | Запросы `POST /api/auth/login` → `GET /api/auth/me`; переход на `/profile` «Личный кабинет» с данными профиля | | |
| LOG-06 | Успешный вход контроллера | `controller@bileton.ru` / `password123` (на API — пользователь с ролью controller) | Переход на `/controller` «Панель контроллера» | | |
| LOG-07 | Сохранение токена | После LOG-05: DevTools → Application → Local Storage | Есть ключ `bileton_access_token` с токеном | | |
| LOG-08 | Токен не светится | После LOG-05 | Токена нет в адресной строке и в Console | | |
| LOG-09 | Заголовок авторизации | После LOG-05: Network → запрос `me` → Headers | `Authorization: Bearer <token>` | | |
| LOG-10 | Ошибка сети (A3) | Только API: остановить backend, войти | Сообщение «Не удалось связаться с сервером…», можно повторить | ⏭ | |
